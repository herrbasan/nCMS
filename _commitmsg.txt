docs(nCMS): rewrite the migration plan top-down

The v1 plan was organised as a component audit arriving at the CMS, and it failed on
first contact ("this works nothing like the old CMS"). Its interaction model was never
written down — it was inferred from components instead of observed from screens.

- docs/CMS_TopDown_View.md: new. The walkthrough record — the one interaction pattern
  (scope axis left, whole-of-scope in a virtualized list right, no pagination), its
  instances (entries / buckets->files / tables->items), the storage model (labels not
  directories, two-stage delete, trash, cold-tier idea), and the nui-link-list gap.
  A reading note tells the reader to view the screens, and the manifest marks which
  screens were walked, which are old reference, and which are missing.

- docs/cms-migration-plan.md: v2, rewritten top-down against that walkthrough.
  v1's framing superseded; its verified facts carried forward (nDB API shape, media
  variant menu, nMedia orchestration rules, invariants, hazards). New: the interaction
  model as the organising idea, a screen inventory, the nui_wc2 composition mapping,
  a revised build order, and a recorded uncertainty about the two editors.

- docs/reference/n000b_cms/: ux-grammar tracked; screenshots updated
  (17-editor-composed-columns.png captured live; a misattributed capture removed).

- .gitignore: tracked (was untracked; it is a real project file).
